Nwely博客 OAuth 2.0 接入文档

本博客系统提供标准的 OAuth 2.0 授权服务，允许第三方应用通过用户的博客账号进行登录。本文档将指导你如何注册应用、完成授权流程并获取用户信息。

1. 概述

你的博客系统内置了一个 OAuth 2.0 授权服务器，支持授权码模式（authorization_code）。主要端点：

· 授权端点：https://你的博客域名/oauth/authorize
· 令牌端点：https://你的博客域名/oauth/token
· 用户信息端点：https://你的博客域名/oauth/userinfo

2. 注册客户端

在开始之前，你需要以管理员身份登录博客后台，注册一个 OAuth 客户端。

请求

```bash
curl -X POST https://你的博客域名/api/oauth/clients \
  -H "Authorization: Bearer 你的管理员Token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "你的应用名称",
    "redirect_uri": "https://你的应用.com/callback"
  }'
```

响应

```json
{
  "success": true,
  "data": {
    "client_id": "client_xxxxxx",
    "client_secret": "生成的密钥"
  }
}
```

请妥善保存 client_secret，它将在换取令牌时使用。

3. 授权流程（用户登录）

3.1 构建授权 URL

将用户引导至以下地址：

```
https://你的博客域名/oauth/authorize?client_id=你的client_id&redirect_uri=你的回调地址&response_type=code&scope=profile email&state=随机字符串
```

参数说明：

· client_id：上一步获取的客户端 ID。
· redirect_uri：必须与注册时一致。
· response_type：固定为 code。
· scope：请求的权限，目前支持 profile（基本信息）和 email（邮箱），多个用空格分隔。
· state：推荐使用随机字符串，用于防止 CSRF 攻击（回调时会原样返回）。

3.2 用户授权

用户登录博客（如果未登录）并同意授权后，浏览器会重定向到你的 redirect_uri，并附带 code 和 state 参数：

```
https://你的应用.com/callback?code=授权码&state=你的state
```

4. 换取访问令牌

用上一步获得的 code，在你的后端服务器发起 POST 请求到令牌端点。

请求

```bash
curl -X POST https://你的博客域名/oauth/token \
  -d "grant_type=authorization_code" \
  -d "code=收到的授权码" \
  -d "redirect_uri=你的回调地址" \
  -d "client_id=你的client_id" \
  -d "client_secret=你的client_secret"
```

成功响应

```json
{
  "access_token": "token_xxxxxx",
  "token_type": "Bearer",
  "expires_in": 7200,
  "scope": "profile email"
}
```

· access_token：后续请求用户信息时使用的令牌。
· expires_in：有效期（秒），目前为 2 小时。

5. 获取用户信息

使用 access_token 调用用户信息端点。

请求

```bash
curl -H "Authorization: Bearer token_xxxxxx" https://你的博客域名/oauth/userinfo
```

响应

```json
{
  "sub": "用户ID",
  "name": "用户名",
  "email": "用户邮箱",
  "picture": "头像URL"
}
```

字段说明：

· sub：用户的唯一 ID（与博客系统内部 ID 一致）。
· name：用户名。
· email：邮箱（可能为 null）。
· picture：头像地址（可能为默认头像）。

6. 错误处理

如果请求失败，端点会返回相应的 HTTP 状态码和错误信息。

示例错误响应

```json
{
  "error": "无效的授权码"
}
```

常见错误码：

· 400：请求参数错误（如缺少必要字段）。
· 401：令牌无效或过期。
· 403：权限不足（如 scope 不匹配）。

7. 完整示例（Node.js）

以下是一个简单的 Node.js 示例，演示了从授权码到获取用户信息的全过程：

```javascript
const axios = require('axios');

const clientId = '你的client_id';
const clientSecret = '你的client_secret';
const redirectUri = 'https://你的应用.com/callback';

// 第一步：重定向用户到授权页面（在你的前端或后端生成URL）
const authUrl = `https://你的博客域名/oauth/authorize?client_id=${clientId}&redirect_uri=${encodeURIComponent(redirectUri)}&response_type=code&scope=profile email&state=${Math.random().toString(36)}`;

// 第二步：在回调路由中处理 code
app.get('/callback', async (req, res) => {
  const { code, state } = req.query;
  // 验证 state（应与之前保存的一致）

  // 换取令牌
  const tokenRes = await axios.post('https://你的博客域名/oauth/token', null, {
    params: {
      grant_type: 'authorization_code',
      code,
      redirect_uri: redirectUri,
      client_id: clientId,
      client_secret: clientSecret,
    },
  });

  const accessToken = tokenRes.data.access_token;

  // 获取用户信息
  const userRes = await axios.get('https://你的博客域名/oauth/userinfo', {
    headers: { Authorization: `Bearer ${accessToken}` },
  });

  console.log('用户信息:', userRes.data);
  // 此时可以创建会话，登录用户
});
```

8. 刷新令牌（可选）

当前实现未提供刷新令牌，令牌过期后需要用户重新授权。如有需求，可联系我们扩展功能。

9. 注意事项

· 所有 OAuth 端点必须使用 HTTPS。
· client_secret 只能在后端使用，严禁暴露在客户端代码中。
· 回调地址必须与注册时完全一致（包括协议、域名、路径）。
· 建议在授权请求中使用 state 参数，并在回调时验证，防止 CSRF 攻击。
