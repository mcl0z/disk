OAuth 2.0 客户端接入文档
本文档指导第三方应用如何接入 Coloryi 博客的 OAuth 2.0 授权服务，使用授权码模式（Authorization Code Grant）获取用户授权，并调用受保护的 API。

基本信息
授权端点：https://blog.coloryi.top/oauth/authorize

令牌端点：https://blog.coloryi.top/oauth/token

受保护的 API 示例：https://blog.coloryi.top/api/user/info（需要 Bearer Token）

1. 注册客户端
在开始之前，您需要在 Coloryi 博客的管理后台注册您的应用，以获取 client_id 和 client_secret。

1.1 注册方式（管理员操作）
目前仅支持博客超级管理员手动创建客户端。请联系管理员并提供以下信息：

应用名称：您的应用名称

重定向 URI：授权成功后用户将被重定向到的地址，必须与后续请求中的 redirect_uri 完全匹配。支持多个，提供 JSON 数组，例如 ["https://yourapp.com/callback", "http://localhost:3000/callback"]

请求的权限范围（可选）：例如 profile（默认，包含用户基本信息），如有特殊需求请与管理员协商。

是否为机密客户端：如果您的应用可以安全保存 client_secret（如后端服务器），选择“是”；如果是纯前端应用（如 SPA），选择“否”（此时应使用 PKCE，本文档以机密客户端为例）。

管理员创建后，您将获得：

client_id：应用的唯一标识

client_secret：应用的密钥，请妥善保管，不要泄露（仅创建时返回一次）

2. 授权流程（Authorization Code Grant）
2.1 步骤概述
引导用户访问授权端点，请求授权码。

用户登录并授权后，重定向回您的应用，并附带授权码。

您的后端使用授权码向令牌端点换取访问令牌和刷新令牌。

使用访问令牌调用受保护的 API。

2.2 请求授权码
构造以下 URL 引导用户访问：

text
https://blog.coloryi.top/oauth/authorize?response_type=code&client_id=YOUR_CLIENT_ID&redirect_uri=YOUR_REDIRECT_URI&scope=YOUR_SCOPE&state=YOUR_STATE
参数说明：

response_type：固定为 code。

client_id：您注册时获得的客户端 ID。

redirect_uri：必须与注册时提供的重定向 URI 之一完全匹配（URL 编码）。

scope：可选，请求的权限范围，默认为 profile。

state：强烈建议提供，用于防止 CSRF 攻击。授权服务器会原样返回此值。

示例：

text
https://blog.coloryi.top/oauth/authorize?response_type=code&client_id=abc123&redirect_uri=https%3A%2F%2Fyourapp.com%2Fcallback&state=xyz789
用户访问后，如果尚未登录，会被重定向到博客的登录页面。登录成功后，将看到授权页面，询问是否允许您的应用访问其信息。用户点击“允许”后，浏览器将重定向到您提供的 redirect_uri，并附带 code 和 state 参数。

重定向示例：

text
https://yourapp.com/callback?code=8a2b3c4d5e6f&state=xyz789
如果用户拒绝授权，将重定向到：

text
https://yourapp.com/callback?error=access_denied&state=xyz789
2.3 换取访问令牌
在您的后端服务器上，使用收到的授权码向令牌端点发起 POST 请求。

请求：

URL：https://blog.coloryi.top/oauth/token

方法：POST

Content-Type：application/x-www-form-urlencoded

请求体（URL 编码）：

参数	值
grant_type	authorization_code
code	上一步获得的授权码
redirect_uri	必须与第一步使用的相同
client_id	您的客户端 ID
client_secret	您的客户端密钥（仅机密客户端需要）
示例（使用 curl）：

bash
curl -X POST https://blog.coloryi.top/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code" \
  -d "code=8a2b3c4d5e6f" \
  -d "redirect_uri=https://yourapp.com/callback" \
  -d "client_id=abc123" \
  -d "client_secret=your_client_secret"
成功响应：

json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "def456ghi789",
  "scope": "profile"
}
错误响应：

json
{
  "error": "invalid_grant"
}
2.4 使用访问令牌调用 API
在后续请求中，将访问令牌放在 Authorization 头中：

text
Authorization: Bearer <access_token>
示例：获取当前用户信息

bash
curl -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..." \
  https://blog.coloryi.top/api/user/info
成功时返回用户基本信息（与博客前端使用的 /api/user/info 相同）。

3. 刷新访问令牌
访问令牌有效期为 1 小时。当令牌过期时，可以使用刷新令牌获取新的访问令牌。

请求：

URL：https://blog.coloryi.top/oauth/token

方法：POST

Content-Type：application/x-www-form-urlencoded

请求体：

参数	值
grant_type	refresh_token
refresh_token	之前获得的刷新令牌
client_id	您的客户端 ID
client_secret	您的客户端密钥（仅机密客户端需要）
scope	可选，如果省略则保持原范围
示例：

bash
curl -X POST https://blog.coloryi.top/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=refresh_token" \
  -d "refresh_token=def456ghi789" \
  -d "client_id=abc123" \
  -d "client_secret=your_client_secret"
成功响应：与授权码换取令牌的响应相同，包含新的 access_token 和 refresh_token（旧的刷新令牌将失效）。

4. 错误处理
令牌端点可能返回以下错误（符合 OAuth 2.0 规范）：

错误	描述
invalid_request	请求缺少必要参数或包含无效参数。
invalid_client	客户端认证失败（client_id/secret 无效）。
invalid_grant	提供的授权码、刷新令牌无效或已过期。
unauthorized_client	客户端无权使用该 grant_type。
unsupported_grant_type	不支持的 grant_type。
invalid_scope	请求的 scope 无效。
授权端点重定向时可能返回的错误（在 URL 参数中）：

错误	描述
access_denied	用户拒绝授权。
invalid_request	请求缺少必要参数。
unauthorized_client	客户端无权使用该授权模式。
unsupported_response_type	不支持的 response_type。
5. 示例代码（Node.js）
以下是一个使用 axios 的完整示例：

javascript
const axios = require('axios');

const config = {
  clientId: 'abc123',
  clientSecret: 'your_client_secret',
  redirectUri: 'https://yourapp.com/callback',
  authEndpoint: 'https://blog.coloryi.top/oauth/authorize',
  tokenEndpoint: 'https://blog.coloryi.top/oauth/token',
};

// 1. 生成授权链接（引导用户访问）
function getAuthUrl(state) {
  const url = new URL(config.authEndpoint);
  url.searchParams.set('response_type', 'code');
  url.searchParams.set('client_id', config.clientId);
  url.searchParams.set('redirect_uri', config.redirectUri);
  url.searchParams.set('state', state);
  url.searchParams.set('scope', 'profile');
  return url.toString();
}

// 2. 用授权码换取令牌
async function getToken(authorizationCode) {
  const params = new URLSearchParams();
  params.append('grant_type', 'authorization_code');
  params.append('code', authorizationCode);
  params.append('redirect_uri', config.redirectUri);
  params.append('client_id', config.clientId);
  params.append('client_secret', config.clientSecret);

  const response = await axios.post(config.tokenEndpoint, params, {
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  });
  return response.data; // { access_token, refresh_token, expires_in, scope }
}

// 3. 使用访问令牌调用 API
async function getUserInfo(accessToken) {
  const response = await axios.get('https://blog.coloryi.top/api/user/info', {
    headers: { Authorization: `Bearer ${accessToken}` },
  });
  return response.data;
}

// 4. 刷新令牌
async function refreshAccessToken(refreshToken) {
  const params = new URLSearchParams();
  params.append('grant_type', 'refresh_token');
  params.append('refresh_token', refreshToken);
  params.append('client_id', config.clientId);
  params.append('client_secret', config.clientSecret);

  const response = await axios.post(config.tokenEndpoint, params, {
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  });
  return response.data;
}
6. 注意事项
安全性：

始终使用 HTTPS。

机密客户端的 client_secret 绝不能暴露在客户端代码中（如浏览器、移动应用）。

对于公共客户端（SPA、移动应用），应使用 PKCE 扩展（本服务暂未实现，如有需要请联系管理员）。

使用 state 参数防止 CSRF 攻击，验证其值与发起请求时的一致。

令牌有效期：

访问令牌有效期为 1 小时。

刷新令牌有效期为 30 天，每次刷新后旧的刷新令牌立即失效，并返回新的刷新令牌。

权限范围：

当前仅支持 profile 范围，返回用户基本信息（用户名、显示名、头像等）。如需更多权限，请联系博客管理员协商。

速率限制：令牌端点可能有限制，请勿高频请求。
